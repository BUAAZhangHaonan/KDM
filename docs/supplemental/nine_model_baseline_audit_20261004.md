# 九模型缺口、补测成本与 baseline 实现核查

日期：2026-10-04。被核查项目提交：`5c777ca817729fc6610174cc26e9654a24065896`。本次只读服务器、已交付数据及作者资料，执行 CPU 计数和公式检查；没有启动新 GPU/Luna 任务，没有修改已冻结输出、评分或论文。

现有 Food 主表和 VizWiz 固定512题的官方评价不依赖下述未闭合的十次试答语义、额外 CDA 分支字段和历史重放证据。它们限制的是模型能力分析和部分机制解释。另一个独立发现是：DoLa、SID 与作者发布代码存在可能影响输出的差异，不能把所有 baseline 写成官方代码的严格复现。

## 1. 为什么没有全部完成，影响什么

| 项目 | 已核实的实际状态与原因 | 受影响的结论 |
|---|---|---|
| Viz 全量十次试答 | 扩展4模型已生成140,040条；复用旧标签后仍有46,439个不同完整QA待语义判断，对应56,651条回复。后期优先闭合用户指定的 Food 主比较、开发选择和 Viz512，完整十答能力队列未收尾；部分旧标签也缺少合格的逐QA阅读/主答案裁定证据。核心5模型现有登记来源只定位到Food十答，尚未定位175,050条Viz十答raw。因此先前仅称“语义标注未闭合”不完整。 | 尚不能给出九模型在全3,501题上的十次作答成功率、模型能力不足参考及其与官方可回答性的交叉验证。现有Food J及Viz512官方连续回答质量、弃权P/R不读取这些标签。 |
| CDA 额外字段 | 权重所需四项校准熵全部保存；缺的是弃权分支熵和完整分支词表向量。原trace写入器没有保存这些量；上一轮CDA核查按授权读取已有trace，没有新增GPU重放。核心5的426,903步已按公式6/7重算通过。 | 不影响已生成回答、C/W/A、J或已保存权重的分组统计。限制公式4完整词表重算、独立argmax校验及弃权分支逐词元解释。 |
| 历史重放来源 | 三模型6条路径9个位置的历史词元与重放argmax不同，gap为0.0625–1.5625。已查到不同硬件和分支调用顺序；历史实际prompt token、视觉张量hash、完整logits及cache/kernel等证据未存全，无法定位单一原因。 | 这6条路径不能声称精确复现并解释了历史每个token。冻结回答及主表计数不受此影响；既有其他测量的代数闭合仍按其实际范围成立。 |

## 2. 能否补、成本多大

GPU小时表示卡数乘运行小时，与排队和并发后的墙钟时间不同。下表明确区分实测依据与规划预算；本次没有新实验计时。

| 补充项目 | 最小工作量 | 成本依据与预算 |
|---|---|---|
| 四扩展模型十答语义收尾 | 46,439个唯一QA，真实Luna判断及必要root复核 | GPU为0。按既有316/521/814条批次从待办到评分闭合的实际窗口，端到端约14–20小时；三Luna并发、root串行的理想规划约10–17小时，尚无该规模实际并发吞吐，不能承诺精确ETA。 |
| 核心5的Viz eval十答 | 先查已登记来源；确实无raw时新增5×3,501×10=175,050条 | 旧Food同一vLLM路线按图计时平移合计6.66 GPU小时，仅预算参考；不含模型加载和后续语义。Viz图像、问题、回复长度不同，应以8图×10答/模型实测后确定成本。 |
| CDA核心5代表面板 | 每类1题，505条完整历史前缀重放，补分支熵/分布记录 | 旧逐样本计时外推纯执行0.59 GPU小时，预留加载/存储约1–2 GPU小时。若全量12,120条重放，旧计时约14.18 GPU小时另加加载/I/O。扩展4模型不套用核心5的精确速率。 |
| 9处重放差异 | 6路径×2调用顺序×2类硬件，保存真实输入、噪声、前缀和分布 | 规划0.5–1 GPU小时，墙钟约30–60分钟；三模型旧有限归因含加载合计983秒为量级依据。新证据只能说明当前复现，无法补成历史未保存的张量。 |
| DoLa作者代码差异验证 | 9模型×8输入×最多3个真实前缀位置=216位置 | 同一批真实分布分别计算两套选层距离；不需Luna。新运行成本须小批计时；若需全量作者口径，再新增21,816条独立输出，仅评分变化回答。 |
| SID作者代码差异验证 | 已准入6模型各8输入，保持相同真实分布对照支持筛选和alpha | 先测实际下一token及自由生成是否变化；不预先重跑14,544条。旧同量生成参考约7.17 GPU小时；小批新成本须实测，不把attention准入证明当作整个算法一致。 |

核心5缺失Viz生成的旧Food速度参考：Qwen2.5-VL 0.69、Qwen3.5-4B 1.06、MiniCPM2.6 0.75、Gemma3-4B 3.23、LLaVA-Mistral 0.93 GPU小时。前四项取原6403单A100，LLaVA取原K100。十答记录中的同一个wall_s按每图只计一次。

DoLa旧完整条件的计时及Gemma184条尾部分片外推，合计约22 GPU小时供全量规模判断；该值混合既有服务器，包含Gemma有偏尾部外推，不是作者版本新运行ETA。具体逐模型/服务器计时保存在分项审计中。

## 3. 所有主表 baseline 的官方实现核对

主表共有69个实际工作点：Direct、原生VCD、DoLa、DeCo、CDA各9个，SID 6个，开发集选择的IP-VCD/IP-M3ID各9个。SID其余3模型无已注册支持。原生M3ID没有独立主表条件；M3ID算子用于IP-M3ID、矩阵和ref-off，以下仍一并核查。

| 方法 | 结论 | 证据与边界 |
|---|---|---|
| Direct | 未发现新的实现问题 | greedy/EOS/32-token遵循统一协议；九模型已有16题/模型共144题真实原生token一致回执。这不是全量所有前缀的逐位证明。 |
| 原生VCD | 分数组合、clean支持及视觉噪声与官方对应 | 使用预处理视觉张量上的timestep500噪声、alpha1/beta0.1。核心5每模型8题共259个生成位置已有真实算子/支持检查；跨模型适配、精度和统一生成协议单列。 |
| DoLa | **与作者代码不等价** | 项目标准JSD符合论文数学名称；作者代码实际为反向KL组合，会选中不同提前层。另有全层候选、重复惩罚1.0相对论文设置的差异。影响九模型21,816条DoLa baseline；实际改变多少回答仍未知。 |
| DeCo | 核心计算符合官方公式与代码 | top-k20/top-p0.9、选层、正向校正、alpha0.6、norm后投影一致。128个CPU非并列算子检查通过；各架构层段按登记比例适配。没有证明BF16并列次序或完整算法全链路逐位相等。 |
| SID | **与官方greedy运行路径不等价** | 官方greedy绕过已计算的beta支持mask；所查包装器没有传入CLI alpha，实际落到默认0.5。项目使用alpha1并保留clean支持mask；选取最低100视觉token也是固定数量适配。六模型attention/mask核已有真实准入，但不能抵消上述解码差异。影响6条件14,544条SID baseline。 |
| CDA视觉迁移版 | 论文公式核对通过，不能称官方原版源码复现 | 四校准熵及公式4/6/7方向对应正式PDF；视觉、空输入和提示属于登记迁移。未定位可确认的作者CDA代码仓库。 |
| M3ID / IP-M3ID底层算子 | 采用主文正号及已登记时间偏移，含明确适配 | 主文Eq4/Algorithm1与补充材料存在印刷符号不一致；采用主文正向对比不能据补充孤立负号判错。项目text-only参考正确，时间偏移采用任务提示长度近似，区别于原论文具体任务的0/10设置；项目生成步从0起，主文Algorithm1从1起。未定位作者官方实现入口，不能写官方代码严格等价。 |

DoLa的CPU构造反例只证明“两个算子可能得到不同结果”，不能当作真实模型回答变化数。SID的作者greedy路径差异也不自动证明哪一种更好；需真实输入定点比较。当前不能声称相对严格作者代码DoLa/SID的胜幅已经验证。原生VCD与IP-VCD的主比较不通过这两个baseline计算，其现有差值仍由冻结回答直接得到。

建议首先补DoLa/SID真实小批差异检验，再决定是否增加独立全量baseline；同步完成低成本CDA/重放记录即可。完整Viz十答用于模型能力交叉分析，优先级低于修正主baseline可比性，不必为这些机制字段重跑整套九模型。
