# 收尾反思

## 延误的具体原因

1. 主评分初期混用了完整回答匹配、宽别名匹配与答案片段匹配，产生了重复评分和补充判断。
2. 将assertive/uncertain、错误/无效等细分列与主准确率耦合，扩大了Luna工作队列。
3. 多次追溯执行记录、重复检查点和小批纠正使结果合并滞后。
4. 主结果收尾期间进入补充机制准备，分散了代码、审阅和沟通时间。

## 本次执行改进

- 使用公开、有限、目标类别无关的名称和弃权规则。
- 一次性合并精确问答复用，逐目标重算正确性。
- 复核集中于主菜角色冲突和真正影响主指标的剩余项。
- 全部已注册方法进入同条件主表，真实分母与逐样本结果直接支撑统计。
- 仓库保留单一可运行入口和最终数据；历史证据压缩归档到项目外。
- 先完成主表、图表、结论和论文，再安排补充机制实验。

## Food-101的常规工作量

Food-101提供101类、101000张图像及现成类别。论文采用每类750训练、250人工清理测试图像。分类器输出一个类别后，评测直接比较类别ID。本项目使用自由文本回答和弃权引导，因此增加名称抽取与弃权识别；这些附加步骤通过规则筛选和有限复核完成。

来源：[官方数据页](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/)；[原论文第5节](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/static/bossard_eccv14_food-101.pdf)。
