# KDM 下一阶段：从置信度现象转向纠错条件

## 唯一主线

对比解码通过相对于参考分布的概率重加权改变答案。概率增加不要求答案变对；纠错则要求正确候选获得足够的相对优势，并在整个生成路径上满足候选约束。现有结果已经显示纠正与致错同时存在，后续研究只增加两类证据：这种操作究竟允许哪些指定名称被生成，以及概率变化是否影响按置信度选择答案。模型的低命名准确率不作为缺少知识的定义。

当前仅凭置信度增加和校准变化，不足以形成有竞争力的 TMM 论文。下面给出的固定规模实验能够补充操作层解释和实际评价后果，但录用与新实验方向都不是已知结果。

## 阅读与执行

研究判断读 `02_DIAGNOSIS.md` 和 `03_NOVELTY_AND_COMPARISON.md`；唯一执行路线读 `01_PLAN.md`、`04_EXPERIMENT_SPEC.md`；数学细节读 `09_OPERATOR_ANALYSIS.md`。执行代理直接使用 `05_PROMPT_FOR_ZCODE.md`，先提交预登记再推理。代码安装后沿用原项目的 `code/`、`data/`、`outputs/`、`cache/` 和 `venv/`。

默认新增模型只有 Qwen3.5-9B 与 LLaVA-v1.6-7B。四模型的完整历史结果保留为主实验基础。物理 GPU 仅允许 0、1、4、5；无需增加 GPU，也不下载新模型。

## 交付内容与实际验证范围

本包包括中文方案、冻结实验规范、ZCode 提示词、七个计算与运行模块、一个含七个绘图函数的模块、自动测试以及七组 PNG/PDF。三组图来自固定提交的真实汇总记录，一组是精确数学例子，三组是明确标注的合成测试示例。合成示例不能进入论文实验结果。

本地已运行数学、统计、数据选择、缓存复用、CPU 模拟模型流程和全部绘图函数。没有在本环境运行真实 VLM 推理，也没有操作服务器或向 KDM 推送代码。完整执行记录见 `verification/VALIDATION_REPORT.md`。真实模型兼容性检查是 ZCode 的首个运行步骤。
