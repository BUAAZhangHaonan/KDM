# Non-census provenance admission review — 2026-09-19

This review covers formal experiment/probe/closed production identities, the mechanism and replay CLI inputs, complete-response audit donors, and the report input chain. It changes no scientific labels, methods, decoding parameters, model adapters, execution-host resolver, or GPU verification programs. No formal generation was run for this review.

## Observed defects and implemented admission

Before this change, mechanism/replay did not inspect raw input sidecars; complete-response audit checked only sidecar digest, row identity and a supplied spec hash; reports checked coverage without binding raw/closed records to a frozen producing identity. A read-only in-memory counterexample passed 74 complete synthetic report tasks containing mixed identities and temperature 9. A separately self-consistent complete-response sidecar with obsolete source, wrong host/backend and temperature 9 also passed the old narrow sidecar helper. These counterexamples establish software admission gaps, not observed corruption of real results.

`src/kdm/task_provenance.py::validate_task_inputs` now validates each sidecar digest and raw row identity against the caller-validated freeze, exact full model spec, frozen source blobs and recorded execution receipt. Portable receipt validation checks the registered producing host, root, GPU UUID/count, registry, resolver and image catalog; it never inspects the consumer host's GPU or local checkpoint availability. A changed spec, source, host, configuration, prompt, sample, task, seed, shard assignment or incomplete task union is rejected.

Each non-census generation identity records an explicit stage, full original dataset-content identity, original manifest byte hash and freeze receipt. Experiment tasks retain the frozen model/dataset method plan; independent probes retain all ten original attempts with temperature 1/top-p 1; closed measurements retain the exact 101 candidates. Mechanism/replay and complete-response audit execute the source gate before constructing a model. Reports validate formal raw and closed inputs before scoring and preserve both source receipts in coverage output. The separate selection provenance helper verifies the existing selection receipt and its census source chain; existing final human-review checks remain required for report labels and complete-response donors.

Shard grouping is by model, stage and declared dataset scope. Within one scope all producing definition fields except `shard` must match. Different valid shards and same-identity file fragments are accepted only when their union covers the entire expected task set without duplicate or unexpected keys. Combining different shard identities into one JSONL while retaining one sidecar is rejected. Mechanism/replay now accept `--records` with multiple paths. Expected task sets are constructed per input scope, not per raw row; the freeze is validated once per entry invocation.

M3ID and instruction-M3ID continue to derive their original offset from the same `backend.encode` call as before. The raw row additionally preserves `offset_prompt_tokens`; consumption checks that the stored offset equals this original token sequence length while every other configuration field equals the fixed method configuration. This is preserved producing evidence, not a claim of independent tokenizer recomputation. Census task construction, row fields and ledger identity fields are unchanged by these additions.

Complete-response audit keeps the entire direct donor pool and its existing truncation/undefined semantics. Its output records both original-input provenance and the measurement execution identity. No EOS fabrication, donor deletion, changed budget, retry, fallback, or scientific-parameter adjustment was introduced.

## Verification and limits

The final CPU validation evidence is `outputs/verification/noncensus_provenance_20260919T131009043544Z/review.json`, with separate full pytest and CLI logs: 355 CPU tests passed in 22.89 seconds and all 28 CLI invocations passed. A subsequent root-requested report path normalization change passed both absolute-path and different-working-directory relative-path cases (2 tests, 0.37 seconds); its exact newer file hashes and log are in `report_paths_followup.json` in the same evidence directory. The suite includes valid source mutations, legal shard unions, changed-host/spec/config cases, probe/closed definition checks, and actual MockBackend production through all three CLI stages followed by the portable consumer gate. Fixtures and temporary files remain under the project root. Mock production is software evidence only.

The evidence receipt also preserves failed iterations and their causes: old isolated entry fixtures needed the new mandatory freeze/spec context; a true producer-to-consumer test caught missing persistence of the newly calculated M3ID offset tokens; the closed-stage CPU fixture needed its image under the explicit nested verification directory. The producer persistence was fixed, and fixture corrections did not weaken admission.

The source gate does not create human decisions or infer semantic correctness from provenance. It does not treat a native interface proof as a formal experiment, a dataset-wide SID proof, or evidence that every response is EOS-complete. Formal use still requires the immutable freeze and the actual registered runtime/method/resource admission checks.
