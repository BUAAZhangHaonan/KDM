# 模型、环境与推理接口

## 完整候选清单

`configs/models.json` 包含16个候选：mprisk中已有13个视觉文本模型，加上既有LLaVA-v1.6-Mistral-7B、LLaVA-v1.5-13B及LLaVA-v1.6-Vicuna-7B。完整清单中的模型都执行同一固定数据清单的直接解码，主条件含弃权引导；无引导条件也完整保存。

模型本地目录以实际config.json、分词器、权重指纹为准。工具记录的mprisk目录与用户原有KDM目录可能不同，执行代理只能在用户给定的只读模型根目录中发现路径。多个路径匹配时明确记录选择依据，不自动替换。`scripts/discover_models.py` 输出候选映射。

## 实际模型接口

迁移器从已读取的 `code/stage3_engine.py` 提取模型构造与输入准备代码，生成 `src/kdm/models/backbone.py`。旧实验循环和旧解码算法不被带入。已知适配覆盖原KDM系列；其他模型优先复用mprisk对应包装代码。

完整普查可以使用本地vLLM接口。对比解码、词元分数、闭集评分和四条件机制使用可访问真实前向分数的模型接口。选中模型需要实现：encode、decode、session；session.next(prefix)返回当前词表logits。`models/hf.py`、`models/mock.py`定义实际调用方式。

MiniCPM的远程forward使用data字典，与普通HF接口不同。其准备过程可直接参考mprisk的 `src/mprisk/models/minicpm_v.py`。Phi及其他远程结构同样使用已有包装。执行代理需要为不兼容模型完成薄适配层，并在对应模型环境中检查。只提供文本API的模型不能被标成已经通过机制计算。

## 必须核查的真实模型条件

固定16条测试图像，逐条比较当前后端与该模型原生generate的直接贪心token序列；完全一致后运行正式生成。比较包括终止词元和可见空格，文本显示归一化单独保存。输入与处理器保持一致。出现差异时修正接口并重新检查全部16条，记录原因；不更改正式数据或研究假设。

四个独立前向条件具有各自的缓存、注意力掩码、位置状态和已生成前缀。代码分别保存Qwen实现中可能存在于共享模型对象的rope_deltas。正式模型需检查交替运行条件与单独运行条件给出的logits一致。

VCD噪声在处理后的pixel_values上生成，采用已登记sigmoid调度和固定文件种子，不转回PIL、不截断像素数值。M3ID的无图输入通过同一处理器的文本模板产生。每一步门控、权重和候选集合均记录。

## GPU与存储

仅使用物理0、1、4、5。12B/13B模型默认占用两张卡，采用显式device_map和max_memory；不允许CPU或磁盘模型卸载。其余模型按实际显存记录设置。运行脚本使用文件锁，双卡进程同时锁定两个编号。

普通模型普查按vLLM支持列表及已有环境执行。其余模型建立项目目录内环境前缀或复用只读conda环境。缓存全部写入项目cache，设置HF_HUB_DISABLE_XET=1。大规模模型分布不写入NPZ；仅保存生成记录、必要标量、候选排序和共享前缀分析。代码按样本读取图片与分布。

## 版本记录

每个模型spec包含模型文件指纹、处理器版本、transformers或vLLM版本、远程代码版本、dtype、思考模式、输入限制、环境Python路径与适配器源码SHA256。断点续跑检查这些身份及任务清单。版本变化创建新的运行目录。
