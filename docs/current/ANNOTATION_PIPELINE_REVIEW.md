## Executable annotation and identity contract

`annotation-queue` includes every supplied response and rejects duplicate keys or changes to an existing queue. Exact whole-response markers and empty outputs receive the documented automatic labels; other outputs require semantic review. Prefilled bypass labels must match both their exact-phrase source and recomputed lexical label. The semantic client sends only question, complete answer and fixed behavior instructions, without generating model, method, task key, gold answer or correctness. Inherited proxies and HTTP redirects are disabled.

The fixed independent checkpoint now lives in `configs/runtime/semantic_judge.json`. The client requires `--judge-spec`, checks the judge is outside the exact frozen subject panel, and verifies GET `/v1/identity` against the spec file, actual service script, versions, GPU allocation and device map. The full service receipt is part of the immutable annotation ledger identity; every completion must carry its digest and `finish_reason=stop`. The parent thread's live handshake evidence is `outputs/verification/judge_service_20260919T0955/client_identity_check.json`; it establishes endpoint identity, not semantic correctness. The service has since stopped.

The parser accepts raw JSON or one complete `json` Markdown fence with no surrounding free text. It retains the exact judge raw content and records the parsing format. Label definitions, evidence requirements and answer-span validation remain unchanged. Multiple JSON objects, extra surrounding prose, incomplete completions, identity mismatches and malformed spans become failures, never substitute labels.

Failures preserve the original response text, question, full HTTP response, input-ledger identity and service receipt digest in `<out>.errors.jsonl`. A failing request does not prevent processing later keys. Any unresolved keys cause an explicit completion summary and exit status 1. Normal resume skips prior failures under the exact same immutable identity; only `--retry-failed` authorizes resubmitting them. Successful keys are never resent. An all-failed run still creates an empty valid annotation ledger for human handling. Transport failures retain a null response body because no response was received.

## Full human-review queue and external decisions

`scripts/human_review.py queue --records ... --annotations automatic.jsonl --errors automatic.jsonl.errors.jsonl --out queue.jsonl` requires exact complete coverage by valid annotations or their recorded failures, with no unknown keys. Failure identity must match the original annotation ledger; original text and question must match raw records. The blinded queue preserves original labels, all failure payloads and raw-record hashes. Priorities include every paired abstention change, invalid or uncertain output, reported ambiguity/disagreement and unresolved judge output. The remaining checklist is fixed to every other supplied formal output, so no new sampling rule is introduced. Failed outputs have `initial_annotation=null`, `judge_parse_failure`, and their raw failures; they are not relabeled invalid.

`merge --queue queue.jsonl --decisions explicitly_submitted.jsonl --out reviewed.jsonl` consumes actual external decision files. Decisions identify key, exact text hash, reviewer, timezone-qualified timestamp, action, revision and previous revision. `revise` additionally requires reason and complete label/evidence/answer_text fields. An unparsed output cannot be approved; it needs an explicit complete revision. Unresolved submissions remain unresolved. Every revision is retained, including the initial automatic label and later adjudicators. Existing output artifacts are immutable.

Formal `select` and `build_reports` require a complete review receipt. Validation checks raw-record identity, required key coverage, original queue, actual decision-file hashes, contiguous chronological revision history and reproducibility of final labels from the original annotation plus submitted decisions. Pending/unresolved outputs block formal use. Receipt metadata cannot replace the underlying decisions. This is provenance and completeness validation, not authentication of the reviewer's physical identity or a guarantee of judgment quality.
